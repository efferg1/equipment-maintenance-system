# 设备点检与故障工单管理系统

把 TPM 里最日常的三件事做成一个可运行的系统：**设备台账 → PM 点检计划 → 故障工单闭环**。

> 崔健　安徽工程大学　软件工程　2027 届　应聘设备工程师

## 一、为什么做这个

设备工程师每天打交道的就是这几件事：

- 哪些设备今天该点检了，谁去检，检什么，判定标准是什么
- 点检发现不合格，怎么变成一张维修工单，谁修，修了多久
- 修完的原因和处理措施有没有留下来，下次再出同样问题能不能查

这三件事在车间里靠纸质点检表和微信群在跑，我就把它做成了一个能真正点得动的系统。做法上还是写代码，但业务逻辑是把 TPM 的 PM 计划、点检执行、故障闭环理清楚。

## 二、功能

### 看板
设备总数、今日到期点检、已逾期未点检、未关闭工单、本月故障数；设备状态分布；今日待检清单（逾期天数标红）；最近点检记录。

### 设备台账
按编号、名称、位置检索；按状态筛选；新增设备；**Excel 批量导入**。

### 点检计划（PM 层）
每个检查项有周期（日检 / 周检 / 月检）、判定标准、责任人、下次到期日。
点检完成后**下次到期日自动按周期顺延**；点检填「不合格」会**自动生成一张故障工单**，直接进维修闭环。

### 故障工单
完整流转：`待派单 → 维修中 → 待验收 → 已关闭`

- 报修：选设备、写故障现象、定级别（高 / 中 / 低）
- 派单：指定维修人
- 维修完成：必须填**故障原因**和**处理措施**（含临时应急措施），系统记完成时间
- 验收关闭：记关闭时间
- 修复时长 = 完成时间 − 报修时间，自动算出来

### 统计分析
- **MTTR**（平均修复时长，分钟）
- 各设备故障次数、高级故障次数、平均修复时长
- 点检结果合格率，按检查项排出谁最容易不合格

## 三、数据模型

```
sys_user        账号（设备管理员 / 维修工 / 操作工）
equipment       设备台账：编号 名称 型号 位置 厂商 投运日期 状态
   ├── check_plan      点检计划：检查项 判定标准 周期 上次点检 下次到期 责任人
   │      └── check_record  点检记录：时间 点检人 结果 OK/NG 实测值 备注
   └── fault_order     故障工单：现象 级别 状态 维修人 原因 处理措施 完成时间 关闭时间
```

设备状态：`RUNNING 运行 / REPAIRING 维修中 / DOWN 停机 / SCRAPPED 报废`
工单状态：`WAITING 待派单 / REPAIRING 维修中 / VERIFYING 待验收 / CLOSED 已关闭`

## 四、技术栈

| 层 | 选型 |
|---|---|
| 语言 | Java 17 |
| 框架 | Spring Boot 3.2.5（Web / Thymeleaf / JDBC） |
| 数据库 | H2（MySQL 兼容模式，内存库，启动自动建表建数据） |
| 数据访问 | JdbcTemplate + 手写 SQL |
| Excel | Apache POI 5.2.5 |

选 H2 是为了**克隆下来就能跑**，不用装 MySQL。SQL 按 MySQL 语法写，换库只改连接串。

## 六、Excel 导入校验规则

表头八列：`设备编号 | 设备名称 | 型号 | 位置 | 厂商 | 投运日期 | 状态 | 备注`

逐行校验：

1. 设备编号非空，且**不与已有编号重复**
2. 设备名称非空
3. 投运日期能按 `yyyy-MM-dd` 解析
4. 状态只能是 运行 / 停机 / 维修中 / 报废

任一项不通过，该行不入库，结果页列出行号和原因，其余合格行照常入库。

## 八、这个项目和设备工程师岗位的对应

| JD 里常写的要求 | 系统里对应的实现 |
|---|---|
| 负责维护保养体系文件的制定 | 点检计划模块：检查项、判定标准、周期、责任人都是可维护的字段，不是写死的文本 |
| 监督 TPM/PM 计划的实施 | 今日到期与逾期清单、点检完成即顺延到期日、点检合格率统计 |
| 负责突发故障维修过程的组织 | 工单四态流转，每一步留时间戳，修复时长自动计算 |
| 应急措施的编制 | 维修完成时必须填处理措施字段，把应急动作沉淀下来可查 |
| 设备状态与维护指标 | MTTR、各设备故障次数与高级故障占比 |

**这个项目证明的不是我会写代码，而是我理解这套流程该怎么跑起来。**
